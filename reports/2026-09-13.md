<section class="copy-section">
<h3>這是什麼</h3>
<p>Worktrunk 用 Rust 撰寫,把「建立分支 + 建立 worktree + cd 過去」這種需要重複打branch 名稱三次的繁瑣流程,簡化成 `wt switch -c` 之類的單一指令,並提供 list/merge/remove 等指令搭配狀態列顯示、hooks 自動化、LLM 產生 commit 訊息、PR checkout 等進階功能。主打場景是同時開多個 Claude Code / Codex agent 平行工作,每個 agent 各自佔用一個 worktree 互不干擾。</p>
</section>
<section class="copy-section">
<h3>值得注意的亮點</h3>
<ul>
<li>三個核心指令(switch/list/merge)取代繁瑣的 git worktree 手動操作,並支援互動式 picker、CI 狀態顯示、LLM 摘要</li>
<li>命令執行採「approve at the gate」設計:專案設定中的 hook/自訂指令需經使用者一次性核准並記錄,避免每次執行都重複詢問,同時降低任意指令被靜默執行的風險</li>
<li>Cargo.toml 顯式設定 unsafe_code = &quot;forbid&quot;,且有獨立的 tests/integration_tests/security.rs 針對 shell injection、NUL 位元組注入等攻擊面撰寫測試</li>
<li>測試覆蓋非常齊全,tests/ 目錄下有上百個 integration test 檔案與大量 insta snapshot,並用 cargo-nextest、cargo-affected、codecov 等工具強化 CI</li>
<li>支援多平台安裝(Homebrew、Cargo、Winget、pacman、conda-forge),Windows 版本另有 SignPath 程式碼簽章</li>
</ul>
</section>
<section class="copy-section">
<h3>適合誰使用</h3>
<ul>
<li>需要同時操作多個 Claude Code / Codex agent 平行開發不同功能分支的工程師</li>
<li>團隊想用 git worktree 加速 code review、PR 並行測試,但嫌原生 git worktree 指令繁瑣</li>
<li>想要在每個 worktree 自動跑 hook(裝依賴、啟動 dev server)並用 LLM 產生 commit 訊息的工作流</li>
</ul>
</section>
