<section class="copy-section">
<h3>這是什麼</h3>
<p>Buzz 是一個以 Rust 建構的自架工作空間，讓人類成員與 AI 代理人共用同一套頻道、文件、工作流程與 Git 事件，底層全部基於 Nostr 的簽名事件日誌。它的核心主張是「一個社群、一套身份模型、一條事件日誌」，讓 AI 代理人不再是旁觀的 bot，而是擁有獨立密鑰與完整審計軌跡的正式成員。目前已支援桌面應用程式（Tauri + React）、buzz-cli、ACP/MCP 整合（Goose、Codex、Claude Code），並提供 YAML 工作流程與 NIP-34 Git 事件。</p>

<section class="copy-section">

<ul>
<li>以 Nostr 協議為基礎，每筆訊息、審查核准、Git 事件皆為密碼學簽名的不可竄改事件，原生支援審計追蹤</li>
<li>AI 代理人被視為一等成員：擁有自己的密鑰、頻道成員資格與審計軌跡，可開 PR、觸發工作流程、調度其他代理人</li>
<li>架構清晰的 Rust crate 工作區（buzz-relay、buzz-acp、buzz-cli 等），並已整合 Goose、Codex、Claude Code 等 LLM 工具鏈</li>
<li>支援「分支即房間」模式：功能分支自動產生頻道，Patch、CI、Code Review 與合併決策全在同一事件流</li>
<li>自架優先（Docker + Postgres + Redis + MinIO），同時也可多租戶部署，社群邊界透過 community-scoped 事件日誌嚴格隔離</li>
</ul>
</section>
<section class="copy-section">
<h3>適合誰使用</h3>
<ul>
<li>希望將 AI 代理人深度整合進開發流程的工程團隊（代理人可直接審 code、寫 release notes、觸發 CI）</li>
<li>重視資料主權、不願將溝通與工作流程交給第三方 SaaS 的組織（完全自架，Apache-2.0）</li>
<li>研究 Nostr 協議在企業協作場景落地的開發者或 AI R&amp;D 工程師</li>

<section class="copy-section">
<h3>這是什麼</h3>
<p>Open Code Review 是一套 Go 撰寫的 CLI 工具,讀取 Git diff 後交給可設定的 LLM(OpenAI/Anthropic 相容)進行代碼審查,產生行級精準的評論,並內建 NPE、執行緒安全、XSS、SQL injection 等調校過的規則集。核心設計是「確定性工程 + Agent」混合架構:檔案篩選、分組、規則比對用工程邏輯保證穩定,只把動態決策交給 LLM Agent,藉此解決一般通用 Agent(如 Claude Code)review 時覆蓋不全、行號漂移、品質不穩定的問題。</p>
</section>
<section class="copy-section">
<h3>值得注意的亮點</h3>
<ul>
<li>阿里巴巴內部大規模驗證(兩年、數萬開發者、數百萬缺陷)後開源的實戰工具,並附真實 PR benchmark(50 repo/200 PR/1505 條人工標註缺陷)證明 precision/F1 優於通用 Agent 且 token 用量僅約 1/9</li>
<li>確定性引擎(檔案篩選、智慧分組、規則比對)搭配 Agent 動態決策的混合架構,設計思路清晰且有明確論述</li>
<li>支援多種審查模式:workspace diff、branch range、單一 commit、全檔案 scan、以及 delegate 模式讓使用者自己的 Agent(Claude Code/Codex/Cursor)執行審查</li>
<li>CI 嚴謹:gofmt 檢查、go vet、govulncheck、race detector、80% 測試覆蓋率門檻、五平台 cross-compile 全部跑在自架 runner 上</li>
<li>有正式 SECURITY.md 揭露流程,且原始碼中可見已修過的實際安全問題(如 ref-option injection,issue #112),顯示團隊有意識地在做威脅建模</li>
</ul>
</section>
<section class="copy-section">
<h3>適合誰使用</h3>
<ul>
<li>在 CI/CD(GitHub Actions/GitLab CI/Gerrit 等)自動化 PR 審查,抓 NPE、執行緒安全、XSS、SQL injection 等常見缺陷</li>
<li>作為 Claude Code / Codex / Cursor 的 skill 或 plugin,用 delegate 模式讓現有 Agent 執行結構化審查而不需另外設定 LLM key</li>
<li>審查沒有 git 歷史的整包程式碼(ocr scan),適合快速盤點不熟悉的舊專案或第三方 repo</li>
<li>團隊想要比通用 Agent 更省 token、更穩定行號定位的專屬 code review 工具</li>
</ul>
</section>
