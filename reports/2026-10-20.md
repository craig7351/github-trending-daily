<div class="repo-copy">
<section class="copy-section">
<h3>這是什麼</h3>
<p>Kronos 是專為金融 K 線(OHLCV)序列設計的 decoder-only 基礎模型家族,已被 AAAI 2026 接受。它先以 BSQuantizer 將連續 K 線量化為階層式離散 token,再用自迴歸 Transformer 預訓練,可用於預測與量化研究。專案提供 Hugging Face 預訓練權重、預測 API、微調流程(Qlib 與 CSV)及 WebUI。</p>
</section>
<section class="copy-section">
<h3>值得注意的亮點</h3>
<ul>
<li>涵蓋全球 45 個以上交易所資料訓練,提供 mini/small/base 三種開源規模(約 4.1M 至 102M 參數),可由 Hugging Face 直接載入</li>
<li>KronosPredictor 封裝正規化、取樣(T/top_p/sample_count)與反正規化,並支援 predict_batch 批次預測</li>
<li>附完整微調流程:Qlib A 股管線(torchrun 多 GPU)與 finetune_csv 的自有 CSV 資料微調</li>
<li>附 WebUI、回測範例與 BTC/USDT 線上 Demo,論文公開於 arXiv</li>
<li>MIT 授權,迴歸測試固定模型 revision,並以種子與容差驗證輸出</li>
</ul>
</section>
<section class="copy-section">
<h3>適合誰使用</h3>
<ul>
<li>以預訓練權重對股票、加密貨幣等 K 線做短期預測實驗</li>
<li>以自有行情資料微調 tokenizer 與預測模型,研究量化因子或訊號</li>
<li>作為金融時間序列基礎模型的研究與論文復現基準</li>
<li>快速搭建 WebUI 展示多資產批次預測結果</li>
</ul>
</section>

<p class="repo-head__summary">在工具輸出、日誌、RAG 片段送進 LLM 之前先於本機壓縮,以節省 token 的 Python 函式庫、代理伺服器與 MCP 伺服器。</p>

<div class="repo-body">
<div class="repo-copy">
<section class="copy-section">
<h3>這是什麼</h3>
<p>Headroom 是一個在本機執行的 context 壓縮層,會依內容類型(JSON、程式碼 AST、文字)選擇不同的壓縮器,並以 CCR 機制在本機保存原文,模型需要時可透過 headroom_retrieve 取回。可當作 Python/TypeScript 函式庫、HTTP 代理、MCP 伺服器使用,也能用 `headroom wrap claude/codex/cursor...` 一行包裝各種程式開發 agent,用來降低 agent 工作流程中的 token 成本與 context 視窗膨脹問題。</p>
</section>
<section class="copy-section">
<h3>值得注意的亮點</h3>
<ul>
<li>多種整合模式:函式庫、proxy、MCP、wrap 指令,支援 Claude Code、Codex、Cursor、Aider 等十多種 agent,且可用 unwrap 還原</li>
<li>內容感知壓縮:SmartCrusher(JSON)、CodeCompressor(AST)、Kompress-v2-base(文字),並附可重現的 seeded 基準腳本</li>
<li>CCR 可逆壓縮:原文存於本機,模型可按需取回;CacheAligner 負責偵測容易破壞 provider prompt cache 的內容,但不會改寫 prompt</li>
<li>額外功能:跨 agent 共用記憶、`headroom learn` 從失敗 session 產出修正規則、輸出 token 精簡</li>
<li>工程成熟度高:數百個測試檔、20 多個 CI workflow(含 CodeQL、security、e2e),並對曾出現供應鏈問題的相依版本明確排除</li>
</ul>
</section>
<section class="copy-section">
<h3>適合誰使用</h3>
<ul>
<li>以 Claude Code / Codex 等 agent 長時間開發,希望降低 token 成本並延長可用 context</li>
<li>在 RAG 或 agent 管線中壓縮大型 JSON、日誌、搜尋結果</li>
<li>為團隊建立統一的 LLM proxy,集中觀測節省量與快取行為</li>
<li>研究 context engineering 與 prompt cache 對齊策略</li>
</ul>
</section>
