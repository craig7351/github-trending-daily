<h3>這是什麼</h3>
<p>pdf-inspector 由 Firecrawl 開發,核心用途是在大量處理 PDF 的流程中先快速分類(文字型/掃描型/圖片型/混合型),讓約 54% 不需要 OCR 的文件可以在 200ms 內於本地完成擷取與轉 Markdown,省下昂貴的 OCR 運算與延遲。除了 Rust 原生 API 與 CLI 工具(pdf2md、detect-pdf),也提供 Python、Node.js 綁定以及瀏覽器 WebAssembly 版本,並支援選擇性 OCR(僅對需要的頁面呼叫本地 PP-OCRv6 模型)。</p>
</section>
<section class="copy-section">
<h3>值得注意的亮點</h3>
<ul>
<li>內建 benchmark 與同類工具(liteparse、opendataloader、pymupdf4llm、markitdown)比較,速度與表格/閱讀順序準確度皆領先</li>
<li>支援多語言綁定:Rust crate、Python (PyPI)、Node.js (napi-rs)、瀏覽器 WASM,涵蓋面廣</li>
<li>分類邏輯不需完整載入文件即可判斷 PDF 類型,300+ 頁 PDF 可在毫秒級完成偵測</li>
<li>支援 CID 字型、ToUnicode CMap、多欄版面、RTL 文字、財務表格等進階 PDF 解析情境</li>
<li>CI 涵蓋 fmt/clippy/測試/跨平台建置/OCR 執行期煙霧測試/WASM,工程紀律扎實</li>
</ul>
</section>
<section class="copy-section">
<h3>適合誰使用</h3>
<ul>
<li>文件處理管線中先分流 PDF,決定要本地擷取還是送往 OCR 服務,節省成本與延遲</li>
<li>將報告、論文、財報、發票等文字型 PDF 快速轉換為結構化 Markdown(含表格、標題、清單)</li>
<li>需要在瀏覽器或 Node.js 環境中不依賴伺服器就能解析 PDF 的應用</li>
<li>RAG / LLM 前處理階段用於清理與結構化 PDF 內容</li>

<li>CHANGELOG 記錄詳盡、CI 涵蓋 Windows/Ubuntu 雙平台、PowerShell 編碼相容性等實務細節,顯示持續維護且非一次性拋出</li>
