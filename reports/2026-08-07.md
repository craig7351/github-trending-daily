<section class="copy-section">
<h3>這是什麼</h3>
<p>code-review-graph(CRG)是一個 local-first 的程式碼智慧圖譜工具,透過 Tree-sitter 解析原始碼建立節點(函式、類別、匯入)與邊(呼叫、繼承、測試覆蓋)的圖譜,並以 MCP 伺服器或 CLI 形式提供給 AI 編碼工具查詢。核心賣點是「blast-radius(影響範圍)分析」:改動一個檔案時,只回傳真正受影響的呼叫者、依賴與測試,讓 AI 助理不必讀整個 repo,官方 benchmark 顯示中位數約 65 倍的 token 減量。</p>
</section>
<section class="copy-section">
<h3>值得注意的亮點</h3>
<ul>
<li>支援 30+ 種語言(Python/JS/TS/Go/Rust/Java/PHP/Ruby 等)與 Jupyter/Databricks notebook,還可透過 languages.toml 自訂語言而不需 fork</li>
<li>提供 30 個 MCP tools 及 5 個 workflow prompt 模板,並可用 --tools 白名單控制暴露的工具數量</li>
<li>支援多平台一鍵安裝(Claude Code、Cursor、Windsurf、Zed、Codex 等 15 種 AI 工具),並附有對稱的 uninstall 指令</li>
<li>官方誠實揭露 benchmark 的侷限性(如 impact recall 1.0 是 graph-derived 的循環上界,並非真實 100% recall),透明度高</li>
<li>CI 涵蓋 ruff lint、mypy 型別檢查、bandit 資安掃描、多版本 pytest(含覆蓋率門檻)以及 Windows 原生測試</li>
</ul>
</section>
<section class="copy-section">
<h3>適合誰使用</h3>
<ul>
<li>為 AI coding agent(Claude Code、Cursor 等)接上 MCP,讓其審查 PR 或大型 repo 時只讀取結構化必要片段,降低 token 成本</li>
<li>在 CI 中以 GitHub Action 針對 PR 產生風險評分留言,標示可能受影響的函式與測試缺口</li>
<li>產生程式庫的社群偵測、架構總覽、Obsidian/GraphML 匯出,協助新人快速理解陌生大型專案</li>
<li>多 repo 場景下用 crg-daemon 背景監看多個專案,自動增量更新圖譜</li>
</ul>
</section>
