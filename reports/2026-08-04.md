<section class="copy-section">
<h3>這是什麼</h3>
<p>pdf-inspector 能在毫秒等級判斷 PDF 是文字型、掃描型還是混合型,並提供逐頁 OCR 路由建議,對文字型 PDF 則直接擷取具座標資訊的內容並轉換成結構化 Markdown(標題、清單、表格、程式碼區塊等)。目標是讓 PDF 處理管線省去多數場景下昂貴且較慢的 OCR 步驟,官方基準測試顯示其在閱讀順序、表格辨識與速度上都優於同類工具。</p>
</section>
<section class="copy-section">
<h3>值得注意的亮點</h3>
<ul>
<li>核心邏輯純 Rust 實作,唯一相依 lopdf,無 ML 模型、無外部服務依賴,官方基準測試 200 份文件僅需 0.47 秒且整體分數贏過 liteparse、pymupdf4llm、markitdown 等對手</li>
<li>偵測邏輯設計細膩,detector.rs 對向量描邊文字、Identity-H 無 ToUnicode、Type3 字型、報紙式多欄版面等邊角案例都有專門啟發式與詳細註解說明校準依據</li>
<li>一次載入文件、偵測與擷取共用同一份解析結果,避免重複 I/O,並提供 EarlyExit/Full/Sample/Pages 多種掃描策略因應不同精度與速度取捨</li>
<li>同時提供 Rust crate、Python(PyO3)、Node.js(napi-rs)與瀏覽器 WebAssembly 四種介面,案例覆蓋主流語言與執行環境</li>
<li>CI 涵蓋 cargo test、rustfmt、clippy(含 WASM 目標)與多作業系統建置,測試包含手造 PDF 樣本與多份真實文件的 Markdown 快照比對</li>
</ul>
</section>
<section class="copy-section">
<h3>適合誰使用</h3>
<ul>
<li>RAG / LLM 文件前處理管線中,快速篩選哪些 PDF 可本地免 OCR 擷取、哪些需送往 OCR 服務</li>
<li>財報、法律文件、發票等結構化表格較多的文字型 PDF 轉 Markdown 供後續解析或索引</li>
<li>瀏覽器端(WebAssembly)本地判斷與擷取 PDF 內容,避免將檔案上傳伺服器</li>
<li>大量 PDF 批次分類任務,需要逐頁 OCR 路由而非整份文件二選一的場景</li>
</ul>
