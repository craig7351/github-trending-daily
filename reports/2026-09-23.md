<section class="copy-section">
<h3>這是什麼</h3>
<p>treg 是一個 FastAPI 架構的「工具版 OpenRouter」:提供單一 base URL + token,agent 就能呼叫 3,000+ 個第三方 API endpoint(SEO、社群、資料 enrichment、廣告等),按次計費且免各家平台自行申請帳號;同時也能讓團隊把自己的 API key、CLI 憑證、Skill 集中託管,由伺服器端注入憑證後轉發,呼叫端永遠拿不到明文密鑰。核心賣點是一個「忠實轉發代理」(relay),只改必要的 header/憑證,其餘原封不動地轉送給上游 API。</p>
</section>
<section class="copy-section">
<h3>值得注意的亮點</h3>
<ul>
<li>核心 relay.py 對忠實轉發(faithful relay)的邊界案例寫得極細:hop-by-hop header 剝離、SSRF 防護(呼叫當下重新解析上游主機、擋內網位址)、防止 treg 自家 session cookie 外洩上游、對回應加 nosniff+CSP sandbox 防止反射式 XSS</li>
<li>測試量體驚人:167 個測試檔、約 3,398 個測試函式,並拆出獨立的 test_ssrf_public_addresses.py、test_security_round2/3/4.py 等安全回歸測試</li>
<li>CI 內建 gitleaks 全歷史秘密掃描並設為必要檢查(reviewers 曾因流程調整不慎跳過,後來補回並在註解中記錄教訓)</li>
<li>架構上用 import-linter 強制分層邊界(輕量 CLI 不得引入伺服器端重量依賴、domain 層不得依賴外層),顯示對長期可維護性的重視</li>
<li>License 為 Apache 2.0 附加條款:允許商用與自架,但禁止未經授權轉售成競品的託管服務</li>
</ul>
</section>
<section class="copy-section">
<h3>適合誰使用</h3>
<ul>
<li>需要讓 AI agent 一次性、低成本地呼叫多家 SaaS API(SEO、enrichment、廣告數據等),而不想逐一申請帳號、管理各家金鑰</li>
<li>團隊想要集中管理內部 API key / OAuth 連線 / CLI 憑證,讓多個開發者的 agent 共用同一份憑證但彼此看不到明文</li>
<li>想在自己的產品內整合 Claude/MCP 工具呼叫,但需要伺服器端代理憑證注入與呼叫稽核紀錄</li>
